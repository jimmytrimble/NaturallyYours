# Naturally Yours — Flutter client (iOS + Android)

A cross-platform client that reuses the existing Naturally Yours API (the Vapor
server on Render). This folder holds the **app source** (`lib/`, `pubspec.yaml`).
The platform runner folders (`android/`, `ios/`, etc.) are generated by Flutter.

Status: **starter slice** — Shop (live product grid + category filter) and Product
detail are wired to `GET /api/products`. Cart, Favorites, Account, Checkout, Contact,
and Admin are ported next.

---

## 1. One-time setup (on your Mac)

```bash
# Install Flutter (includes Dart)
brew install --cask flutter        # or: https://docs.flutter.dev/get-started/install/macos

# Android toolchain (to build/run on Android)
brew install --cask android-studio # then open it once: install Android SDK + an emulator
# iOS toolchain is already present (Xcode).

flutter doctor                     # follow any ticks it asks you to resolve
```

## 2. Generate the platform projects around this source

Flutter needs to create the `android/`/`ios/` runners. From the repo root:

```bash
cd flutter_app
flutter create .                   # generates android/, ios/, etc. — keeps lib/ & pubspec
flutter pub get
```

(`flutter create .` is safe here: it adds the missing runner folders without
overwriting `lib/` or your `pubspec.yaml`.)

## 3. Run it

```bash
flutter devices                    # list simulators/emulators/connected phones
flutter run                        # pick a target, or:
flutter run -d chrome              # quick smoke test in a browser (web)
```

You should see the **Shop** tab load products from the live server.

## Build a test build for an Android phone (before release)

Easiest for one or two testers — **sideload an APK** (no store, no fee):

```bash
flutter build apk --release
# output: build/app/outputs/flutter-apk/app-release.apk
```
Send that `.apk` to the tester. On their Android phone: open the file, allow
"Install unknown apps" for the app they opened it from, then install.

Scales better — **Google Play internal testing** (the TestFlight analog):
1. Join the Google Play Console ($25 one-time).
2. Build an app bundle: `flutter build appbundle --release` → `build/app/outputs/bundle/release/app-release.aab`.
3. Play Console → your app → Testing → **Internal testing** → upload the `.aab`,
   add testers by email (or share the opt-in link). They install via Google Play.

## Architecture notes
- `config.dart` — API base URL (points at the Render server).
- `api_client.dart` — read-only JSON client + image URL resolver.
- `models/` — Dart models mirroring the server DTOs (camelCase JSON).
- `services/` — API calls grouped by domain.
- `screens/` — UI.
- `theme.dart` — brand pink theme, light/dark via `ThemeMode.system`.

When we port **cart/auth** (which use server session cookies), we'll switch the
HTTP layer to `dio` + `cookie_jar` (dependencies are listed, commented, in
`pubspec.yaml`) so the session cookie persists like it does on iOS.
